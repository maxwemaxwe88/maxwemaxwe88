# Техническое Задание (ТЗ) на разработку Крипто-Скринера

**Название проекта**: Cross-Exchange Open Interest Screener  
**Цель**: Создание десктопного приложения или веб-сервиса для мониторинга и поиска аномального роста Открытого Интереса (Open Interest, OI) на фьючерсных рынках криптовалют.

---

## 1. Общее Описание
Приложение должно агрегировать данные с множества криптовалютных бирж в режиме реального времени, отображать их в едином интерфейсе в виде "плиток" (карточек) для каждой биржи и позволять сортировать инструменты по изменению Открытого Интереса (OI). Основная задача — выявление пампов/дампов и притока ликвидности на ранней стадии.

## 2. Поддерживаемые Биржи и Рынки
Приложение должно поддерживать подключение к следующим биржам (секция Futures/Perpetual Swap):

1.  **Binance** (USDT Futures)
2.  **Bybit** (USDT & USDC Perpetuals)
3.  **OKX** (Swap)
4.  **Bitget** (Futures)
5.  **Gate.io** (Futures)
6.  **KuCoin** (Futures)
7.  **MEXC** (Futures)
8.  **BingX** (Futures)
9.  **HTX** (Huobi Futures)
10. **BitMart** (Futures)
11. **HyperLiquid** (DEX Perps)
12. **Deribit** (Options/Futures)
13. *Опционально*: LBank, AsterDex (если доступно API)

## 3. Функциональные Требования

### 3.1. Сбор Данных (Backend)
- **Многопоточность/Асинхронность**: Параллельный опрос API всех бирж для минимизации задержек.
- **Данные**:
    - Символ (Тикер)
    - Текущая цена (Price)
    - Открытый Интерес (Open Interest) в базовом активе и в USD.
    - Изменение OI за периоды: 5 мин, 15 мин, 1 час, 4 часа, 24 часа.
    - Объем торгов (Volume 24h).
- **Rate Limits**: Умная обработка лимитов запросов API (очереди, задержки, ротация прокси при необходимости).

### 3.2. Интерфейс (Frontend)
- **Grid Layout**: Отображение каждой биржи в отдельном контейнере (виджете/окне).
- **Сортировка**:
    - По умолчанию: По убыванию % изменения OI (ищем всплески).
    - Возможность сортировки по объему OI (USD), Цене, Тикеру.
- **Визуализация**:
    - Цветовая индикация роста (зеленый) и падения (красный) OI.
    - Мини-графики (sparklines) для динамики OI (опционально).
- **Фильтрация**:
    - Исключение низколиквидных пар (фильтр по мин. объему или мин. OI).
    - Поиск по тикеру.

## 4. Технический Стек (Рекомендованный)

### Вариант А: Веб-приложение (как текущий прототип)
- **Backend**: Python (FastAPI) + CCXT (библиотека для унификации API бирж).
- **Frontend**: React (Vite) + TailwindCSS.
- **Хранение**: Redis (для кеширования текущих состояний и быстрого расчета дельты изменений) или In-Memory Python dicts (для MVP).

### Вариант Б: Десктопное приложение (Electron)
- **Core**: Electron.js.
- **UI**: React/Vue.
- **Logic**: Может использовать тот же Python backend как микросервис, либо использовать CCXT (JavaScript версия) внутри Node.js процесса.

## 5. Алгоритм Расчета Изменения OI
Так как многие биржи отдают только *текущее* значение OI:
1.  Скринер должен хранить историю значений OI (TimeSeries).
2.  `Delta OI % = ((Current OI - Previous OI) / Previous OI) * 100`
3.  Необходимо накапливать историю минимум за 24 часа для полноценного анализа.

## 6. Требования к Производительности
- Частота обновления данных: не реже 1 раза в 10-60 секунд (в зависимости от лимитов бирж).
- Задержка отображения: минимальная.

## 7. Этапы Разработки
1.  **MVP**: Подключение топ-5 бирж, табличный вывод, сортировка по текущему значению (без истории).
2.  **History & Delta**: Реализация базы данных/кеша для хранения истории и расчета изменений (1h, 4h).
3.  **UI Polish**: Улучшение визуализации, добавление графиков.
4.  **Scale**: Добавление всех остальных бирж (Gate, KuCoin и др.), решение проблем с прокси.
